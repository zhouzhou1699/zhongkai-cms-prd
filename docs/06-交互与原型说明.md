# 交互与原型说明

> 配套可点原型：[prototype/index.html](../prototype/index.html)（双击即开，零依赖）。
> 本文说明设计思路、关键流程走查、异常态处理。原型里能点的东西，这里都解释了为什么这么设计。

## 一、三条设计原则

### 1. 「导航即 IA」——不要翻译层

后台左侧导航树 = 官网 IA 树，1:1 映射。运营在后台点到「服务官网 › 产品超市 › 3D点云标注平台」，心里想的和访客看到的路径完全一致。

**反例**（很多 CMS 的做法）：后台按「内容类型」组织（所有文章、所有产品、所有页面），运营每次都要做一次「我要改的那个东西属于哪个类型」的转译。对每 5 分钟就要改一次文案的人来说，这个转译成本每天累加。

### 2. 「字段即对象」——不暴露数据结构

运营看到的是：

```
首屏主标语        [ 数据驱动智能，要素赋能未来                    ]
首屏副标语        [ 专注人工智能数据服务…                        ]
走进我们 · 配图   [ 缩略图 ] [上传新图片] [从图库选择] [清除]
```

而不是：

```json
{"home_service": {"hero_title": {"v": "数据驱动智能…", "type": "text"}}}
```

**判断标准**：把后台截图给一个没用过的人，他能不能在 10 秒内找到「改电话」的地方。能，就对了。

### 3. 「危险操作必须有前置成本」

| 操作 | 前置成本 | 为什么 |
|---|---|---|
| 保存 | 无 | 高频、可撤销（历史版本） |
| 发布 | 无（但自动备份） | 高频、可回滚 |
| 强制覆盖（冲突时） | 二次确认 + 显示差异 | 会抹掉同事的工作 |
| 删除产品 / 基地 | 二次确认 + 输入名称 | 会删 HTML + 清所有相关推荐引用 |
| 批量替换 | 先显示命中数 → 确认 → 自动备份 | 影响面不可肉眼预估 |
| 删除被引用的图 | 阻塞（409）+ 列出引用页面 | 会造成线上裂图 |

## 二、关键流程走查

### 流程 A：改一个全站通用的电话（最高频）

```
① 打开后台（1 次点击，会话保持 12h）
   └ 左栏顶部搜索框可直接输入「电话」→ 跳到字段

② 左侧「全站通用信息」
   └ 右侧 11 个字段平铺，第一个就是「客服电话」

③ 改值
   └ 顶部栏出现「● 有未发布的修改」
   └ 同时「保存」按钮从描边变实心（视觉提示：该保存了）

④ 预览（可选但推荐）
   └ 点「预览修改」→ 新标签打开整站 → 右上角黄色「预览」角标 + 「返回编辑」
   └ 线上零字节变动

⑤ 发布
   └ 点「保存并发布」→ 进度面板：
       [1/5] 读取内容… 
       [2/5] 计算影响面：改了「全站通用信息」，需重建全部 41 页
       [3/5] 备份 41 页 + 内容 → _backup_publish/20261114-1602/
       [4/5] 构建 41/41 页（0.22s）
       [5/5] 完成 ✓ 点击查看线上
```

**设计要点**：
- 第 3 步必须让「有未发布修改」显式可见。否则运营会以为保存了就上线了。
- 第 5 步必须**先告诉用户要重建多少页、为什么**。黑盒式的「发布中…」会让人不敢用。
- 完成态要有「看线上」的直链，形成闭环。

### 流程 B：新增一个产品（最高价值）

```
① 产品超市 → 右上「+ 新增产品」
② 填：名称 / 别名(slug) / 中文角标 / 英文角标 / 类型(软件|硬件) / 一句话定位
③ 保存 → 系统自动：
   - 生成 product-<slug>.html（模板化 5 字段）
   - 加入左侧导航树
   - 加入产品超市对应分区（软件/硬件）
   - 加入首页产品卡片
   - 可被选入其他产品的「相关推荐」
④ 进产品页填 5 个字段（简介 / 详细介绍 / 4 张能力卡 / 6 行规格 / 4 个相关推荐）
⑤ 发布
```

**关键设计**：第 ③ 步的「自动联动」是这套系统的核心价值。如果新增产品后还要手动加导航、手动加列表项，那它和外包没有区别。

**删除产品时的连锁处理**（容易被忽略）：
- 删 HTML 文件
- 从导航移除
- 从产品超市移除
- 从首页卡片移除
- **清理其他产品页 `related` 里指向它的引用**（`_drop_related_refs`）
- 从独立站 manifest 移除

### 流程 C：多人并发冲突

```
运营 A：打开 → 改首页标题 → 保存 ✓（rev 51 → 52）
运营 B（同一时刻打开，rev 51）：改产品页简介 → 保存 ✗

弹窗：
  ┌─────────────────────────────────────────┐
  │ ⚠ 有更新的修改                            │
  │ admin 在 16:02 保存了 1 处改动：           │
  │   首页 › 首屏主标语                        │
  │   「数据驱动智能…」→「数据驱动智能，赋能…」 │
  │                                          │
  │ 你的修改（产品页简介）没有丢失。            │
  │ [ 刷新并重做 ] [ 强制覆盖（会抹掉对方改动） ]│
  └─────────────────────────────────────────┘
```

**设计要点**：
- 必须明确告诉用户「**你的修改没有丢失**」——这是冲突弹窗里最重要的一句话，否则人会慌。
- 必须列出对方的改动是什么，让用户能判断谁该让步。
- 「强制覆盖」用危险色 + 明确说明后果，不放在顺手位置。

### 流程 D：发布失败

```
进度面板：
  [3/5] 构建 27/41 页…
  ✗ product-geo.html 失败：KeyError 'feats'
  
  ┌──────────────────────────────────────────┐
  │ 发布已中止，站点已回滚到发布前状态。         │
  │ 41 个页面文件与发布前完全一致，线上没有变化。 │
  │                                          │
  │ 失败页面：product-geo.html                │
  │ 原因：核心能力卡片说明缺少 1 条（需要 4 条）  │
  │                                          │
  │ [ 去修 product-geo 的能力卡 ] [ 看详细日志 ] │
  └──────────────────────────────────────────┘
```

**设计要点**：
- 第一句话必须回答「**线上现在是什么状态**」。
- 原因必须是**运营能看懂的人话**，而不是 Python traceback。技术细节收进「看详细日志」。
- 必须给「去修 N 处」的直达链接——这是把错误提示变成行动。

### 流程 E：找一个词并批量替换

```
① 左栏搜索框输入「2024」
② 结果列表：
   服务官网 › 关于中开服务 › 公司速览  第 2 项          「成立于 2024 年」
   集团官网 › 走进中开 › 集团概况 · 第 3 段             「2024 年，集团…」
   …（共 7 处）
③ 点任一条 → 跳到该页面 + 滚动到字段 + 高亮关键词
④ 或点「批量替换」→ 输入新词 → 预览命中 7 处 → 确认 → 自动备份 → 执行
```

**设计要点**：搜索必须能搜到「字段里的值」，不只是页面标题。技术实现是把 content.json 摊平成 `{路径: 值}` 再全文匹配。

## 三、状态设计（每个页面都要有的四态）

| 状态 | 表现 | 为什么必须画 |
|---|---|---|
| 默认 | 正常内容 | — |
| 有未发布修改 | 顶部红点 + 「保存」按钮变实心 | 区分「已保存」与「已发布」 |
| 空状态 | 不用「暂无数据」，给下一步动作 | 空状态是新手第一次见到的界面 |
| 加载 / 发布中 | 逐步骤进度，不是转圈 | 3 秒以上的等待必须给进度感 |
| 错误 | 人话 + 行动链接 | 见流程 D |

原型里这四态都可以切换（右上角状态开关）。

## 四、视觉规范（后台）

| 项 | 值 | 理由 |
|---|---|---|
| 主色 | `#2563eb`（蓝） | 工具型产品用中性蓝，不用品牌色抢焦点 |
| 危险色 | `#dc2626` | 只用于删除 / 强制覆盖 |
| 文字 | `#111827` / `#6b7280` | 两级足够，避免灰阶混乱 |
| 边框 | `#e5e7eb` | 1px，弱化表格线 |
| 圆角 | 6px（控件）/ 10px（卡片） | — |
| 字号 | 13px 正文 / 12px 辅助 / 15px 页面标题 | 后台信息密度高，正文不宜大于 14 |
| 间距 | 8 的倍数 | — |
| 表单标签 | 上方，14px 中等字重 + 可选 hint 小字 | 左标签在字段多时会造成锯齿 |

## 五、文案规范

| 场景 | ❌ 不要 | ✅ 要 |
|---|---|---|
| 空列表 | 暂无数据 | 还没有产品。点右上「新增产品」开始，或先从现有产品复制一个。 |
| 保存成功 | 操作成功 | 已保存 3 处修改（未发布） |
| 发布成功 | 发布成功 | 已上线 41 页，用时 0.22s。[查看线上] |
| 发布失败 | 生成器异常，请联系技术 | 发布已中止并回滚，线上没有变化。失败页 product-geo：能力卡需要 4 条，当前 3 条。[去修] |
| 权限不足 | 403 Forbidden | 只有管理员能回滚。需要的话找 @内容负责人。 |
| 表单校验 | 格式错误 | 电话建议用「区号-号码」格式，例如 0633-8888888 |

**一条总原则**：错误提示必须包含三件事——**发生了什么、现在什么状态、下一步点哪里**。

## 六、原型使用说明

打开 [prototype/index.html](../prototype/index.html)：

| 区域 | 内容 | 可交互 |
|---|---|---|
| 左栏 | 41 页真实 IA 树（可展开/折叠，点页面切换） | ✅ |
| 中栏 | 字段编辑器：13 种类型的真实控件；改值会实时更新「未发布」计数 | ✅ |
| 右栏 | 发布状态机（idle → running → done / rolled_back）、影响面计算、优化前后对比 | ✅ 点「发布」可看全过程 |
| 顶栏 | 保存 / 保存并发布 / 预览修改 / 用户菜单 | ✅ |
| 右上状态开关 | 默认 / 有未发布 / 冲突 / 发布失败 / 空状态 | ✅ |

原型数据来自真实系统的 `data/fields.json`（218 字段），不是编的。所以它同时也是一份「字段字典的可视化版本」。
