## 1. 产品定义

**一句话**：一个后台，管两个官网 + 一批产品独立站；内容的唯一真源是一个 JSON，页面的唯一产物是一批静态 HTML。

**它不是**：不是可视化建站工具（不能让用户拖拽布局），不是博客系统（资讯只是内容类型之一），不是营销自动化（不做线索评分与培育——但下一步要做线索收集，见 F-17）。

**它必须是**：任何一次内容改动，都能在 4 步内安全上线；任何一次上线，都能在 1 次点击内完全撤销。

## 2. 系统架构

```
┌──────────────────────────────────────────────────────────────────┐
│ 内容层  _build/content.json  (145 KB / 218 字段节点)               │
│   顶层：site(11) home_service(10) home_group(11) news_page(1)     │
│         bases{7} pages{26} products[15] version rev               │
│   字段形状：{"v": 值, "label": "中文名", "type": "text", "hint": …}│
└───────────┬──────────────────────────────────┬───────────────────┘
            │ cv() / cvl() 只读                  │ HTTP JSON 读 / 写
┌───────────▼────────────────┐    ┌────────────▼───────────────────┐
│ 渲染层  _build/             │    │ 后台层  admin/                  │
│  common.py      1,664 行    │    │  server.py  3,039 行（纯标准库）│
│  pagebuild.py     337 行    │    │  app.js     2,416 行            │
│  gen_home        516        │    │  admin.css    908 行            │
│  gen_service     680        │    │  35 个接口 / 2 角色 / 审计        │
│  gen_group       773        │    └────────────┬───────────────────┘
│  gen_product_details 178    │                 │ subprocess / 线程
│  gen_base_details  144      │◄────────────────┘
│  gen_product_sites 214      │
│  gen_wechat_news   588      │
│  → 41 个 HTML（静态）        │
└───────────┬─────────────────┘
            │ Nginx 静态托管（443 → 内部 6993 单端口）
┌───────────▼──────────────────────────────────────────────────────┐
│ 访问层：服务官网 / 集团官网 / 3 个产品独立站（端口 4123–4125）      │
└──────────────────────────────────────────────────────────────────┘
```

**为什么单端口**：官网、登录页、后台、接口都在 6993。少一个端口就少一处 CORS、少一套 Cookie 域配置、少一份运维文档。

## 3. 核心概念（必须先统一，否则后面全错）

| 概念 | 定义 | 常见误解 |
|---|---|---|
| **内容（content）** | 存在 content.json 里的数据，是唯一真源 | ❌ 不是 HTML；HTML 是产物，手改会被下次发布覆盖 |
| **保存（save）** | 把内存里的编辑写回 content.json，rev +1 | ❌ 不等于上线。保存后官网还是旧的 |
| **发布（publish）** | 读 content.json → 算出要重建哪些页 → 备份 → 重建 → 完成 | ❌ 不是全量重建（有增量）；✅ 失败会自动回滚 |
| **预览（preview）** | 用当前内存内容渲染到 `_preview/`，线上零字节变动 | ❌ 预览不是「打开已发布的页面」 |
| **基线（published baseline）** | 上一次成功发布时的 content 快照，用于算增量 | 只有真正重建过才推进基线；跳过重建不能推进（否则清空类改动永远判「无变化」） |
| **注册表（registry）** | products[] / bases{}，驱动导航、列表、相关推荐 | 不是普通内容，改它会触发全站重建 |

## 4. 功能规格

### 4.1 后台信息架构

```
├─ 全站通用信息（11 字段：电话/邮箱/地址/备案号/工作时间/页脚文案…）
├─ 服务官网
│   ├─ 首页（10 字段）
│   ├─ 产品超市（2 字段：软件简介行 / 硬件简介行）+ 15 个产品详情（各 5 字段）
│   ├─ 解决方案（4 个方案块）
│   ├─ 校企实训（3 个板块）
│   ├─ AI 解决方案（软件开发 9 / 智能体 3 / 端侧 5）
│   ├─ 数据工厂 · 模型工厂 · 客服基地
│   └─ 关于中开服务
├─ 集团官网
│   ├─ 首页（11 字段，含资讯）
│   ├─ 走进中开（6 段长文）
│   ├─ 业务板块（7 块）
│   ├─ 园区基地（列表 + 7 个基地详情，各 11 字段）
│   └─ 中开资讯（3 分类 / 文章 CRUD）
└─ 站点工具
    ├─ SEO 设置（逐页 title / description 覆盖）
    ├─ 历史版本（60 份 + 字段级 diff + 恢复）
    ├─ 备份与恢复（页面 / 页面+内容）
    ├─ 账号管理（admin / editor）
    ├─ 操作日志（20+ 类动作）
    ├─ 公众号同步（扫码 / 续期 / 解绑 / 立即同步）
    └─ 图片库（上传 / 压缩 / 引用保护 / 清理未引用）
```

### 4.2 字段编辑器：13 种类型

| 类型 | 控件 | 用于 | 特殊行为 |
|---|---|---|---|
| `text` | 单行输入 | 标题、电话、备案号 | 超长自动截断提示 |
| `longtext` | 多行文本域 | 简介、详细介绍 | 允许 `<br>`（一期妥协，二期改 Markdown） |
| `paras` | 动态行数组（增 / 删 / 上下移 / 序号） | 正文段落、能力卡说明 | 可带 `names[]` 作为行标题，`edit_names` 控制标题是否可改 |
| `cells` | 固定 2–4 列组合 | 公司速览条 | 列数固定，值可变 |
| `stats` | 数字 + 单位对 | 首页统计条 | 数字与单位分开编辑 |
| `image` | 上传 / 图库选择 / 清除 + 预览 | 配图、头图 | 上传即压缩（最长边 1920 / WebP） |
| `tags` | 逗号分隔标签 | 基地标签 | 提交时 trim + 去空 |
| `number` | 数字 | 渐变角度、席位数 | 带范围 hint（90–200） |
| `blocks` | 结构块数组（标题 + 描述 + 要点 + 图） | 解决方案、实训、业务板块 | 每块内部多字段联动 |
| `tabs` | 标签页数组 | 企业理念 | 标签名 + 正文 |
| `milestones` | 年份 + 事件 | 发展历程 | 按年份排序 |
| `news` | 分类 + 文章列表（日期 / 标题 / 图 / 正文块） | 资讯 | 正文块支持段落 / 小标题 / 图片 / 链接 / 视频 |
| `news_page` | 分类元数据 | 资讯页 | — |

**设计原则**：字段类型不是技术分类，是**编辑动作的分类**。运营要「加一段话」→ `paras`；要「换张图」→ `image`；要「改个数字」→ `number`。技术上是 JSON 数组还是对象，运营不需要知道。

### 4.3 保存：乐观锁

```
GET  /api/content        → {content, rev}
POST /api/content        → body.rev 必须等于服务端 rev
  相等   → 写盘，rev + 1，返回 {ok, rev, changed}
  不相等 → 409 {error:"有更新的修改", diff:[字段级差异]}
```

- `changed` 是本次改动处数（前端展示「已保存 3 处」）。
- 409 时前端弹窗列出「A 同事在你之前改了：首页/首屏主标题」，提供「强制覆盖」按钮（明确二次确认）。
- 保存走跨进程文件锁（`_build/.content.lock`），与公众号同步任务共用，避免「同步写入 2 篇 → 运营旧副本保存 → 文章被抹」。

### 4.4 发布：增量 + 原子 + 可回滚

**状态机**：

```
idle ──publish_start──► running ──成功──► done(ok=true)
                          │
                          ├──某页失败──► 自动回滚 41 页 + 内容 ──► done(ok=false, rolled_back=true)
                          └──内容无变化──► done(ok=true, mode="none", pages=0)
running 期间再次 publish → 409「上一个发布还在进行中」
```

**执行顺序（每一步都可观测）**：

1. **预检**：读 content.json，解析失败直接拒绝（不动任何页面）。
2. **算计划**：`diff(基线, 当前)` → 改动路径 → `_targets_for(paths)` → 目标页集合 + 模式（incremental / full / none）。
3. **备份**：把 41 个 HTML + content.json + meta 打包到 `_build/_backup_publish/<时间戳>/`。备份**必须含内容**——只备 HTML 的话，恢复后下一次发布会用新内容再覆盖一遍。
4. **构建**：单进程内按页调用构建函数，逐页回报 `{page, ms, ok}`。
5. **收尾**：套 SEO 覆盖 → 刷新 sitemap.xml / robots.txt → 推进基线 → 写 `published_at / published_rev`。
6. **失败处理**：任一页抛错 → 用第 3 步的备份还原全部页面 + 内容 → 标记 `rolled_back=true` → 前端显示「已回滚到发布前，站点未变」+ 失败页与原因。

**影响面规则（关键，写死在这里，不许模糊）**：

| 改动路径 | 重建范围 | 原因 |
|---|---|---|
| `site.*` | **全量 41 页** | 页脚出现在每一页 |
| `products[]` | **全量** | 全站导航下拉 + 产品超市 + 首页卡片都要重排 |
| `home_service.*` | `index.html` | — |
| `home_group.*` | `group.html` | — |
| `news_page.*` | `index.html` + `group-news.html` + 全部资讯正文 | 首页资讯区也读 news_page |
| `bases.<slug>.*` | 该基地页 + `group-bases.html`；若改的是 name/alias/prov 再带上集团站各页 | 导航下拉显示基地名 |
| `pages.<id>.*` | 该页自己；若该页是产品页，连带产品独立站 | — |
| 基线不存在 | **全量** | 升级后第一次发布，必须先建基线 |

### 4.5 预览

`POST /api/preview` → 服务端把当前内存内容写到临时文件 → 用 `ZK_CONTENT_PATH` + `ZK_SITE_ROOT` 环境变量把整站渲染到 `_preview/` → 返回可访问地址 → 预览页带「预览」角标与「返回编辑」浮层。

- 只生成对外页与资讯，不生成产品独立站（无必要，且端口冲突）。
- 预览是「整站可点」的，不是单页快照——因为运营经常要验证「从首页能不能点到这个产品」。

### 4.6 历史版本

- 每次保存写一份快照到 `_build/_versions/<时间戳>.json`，保留 60 份。
- 「历史」抽屉：列表（时间 / 账号 / 改动处数）→ 点开看字段级 diff（左旧右新，按字段路径对齐）→ 一键恢复（恢复本身也生成一份新快照，可再撤回）。

### 4.7 搜索与批量替换

- `GET /api/search?q=` 扫 content.json 全字段，返回 `{page, field_label, path, snippet}`。
- 点结果 → 前端跳到该页面 + 该字段 + 高亮。
- `POST /api/replace`：先返回命中数与预览，二次确认后执行，执行前自动备份。**不做正则**（运营会用错，且正则替换无法预估影响）。

### 4.8 账号与审计

- `admin/users.json`：`{user: {role, salt, hash, must_change}}`，PBKDF2（15 万轮）。
- 会话落 `admin/sessions.json`，12 h 过期；改密 / 登出踢全部会话。
- 首登强制改密（新密码 ≥8 位且不同于原密码）。
- 连续输错：同 IP 5 次 / 同账号 10 次 → 锁 5 分钟。
- `admin/audit.log`：`时间 / 账号 / IP / 动作 / 对象 / 备注`，覆盖登录、保存、发布、回滚、增删、上传、改密、账号变更等 20+ 类。

### 4.9 SEO 设置

逐页覆盖 `<title>` 与 `<meta description>`，只做正则替换，不改生成器模板。保留原品牌后缀（`产品超市 | 中开科技` → `新标题 | 中开科技`）。

### 4.10 公众号同步

每日 08:30：playwright 扫码态登录 → 拉文章列表 → 合并进 `news_page.cats` → 写 content.json（走同一把锁、bump rev）→ 触发发布 → git commit/push。后台提供扫码续期 / 换绑 / 解绑 / 立即同步一次的 UI。

## 5. 非功能需求

| 类别 | 要求 | 实测 |
|---|---|---|
| 发布性能 | 全量 < 1 s；单页 < 0.1 s；无变化 < 0.3 s | 0.22 s / 0.07 s / 0.27 s |
| 并发 | 同一时刻只允许 1 个发布；保存并发必须检测冲突 | 第二个 publish 409；双浏览器保存 409 |
| 数据安全 | 任何写操作原子（临时文件 + `os.replace`）；任何破坏性操作前有备份 | 全部满足 |
| 可恢复 | 发布失败站点零变化；内容可从 60 份快照或 git 恢复 | 人为杀生成器验证 41 页哈希不变 |
| 兼容 | Python 3.6+（CentOS 7）；无第三方依赖；离线可跑 | 是 |
| 响应 | 后台首屏 < 1.5 s（本机）；页面切换 < 200 ms | 满足 |
| 可访问性 | 键盘可达；表单有 label；对比度 ≥ 4.5:1 | 后台满足，前台部分待补 |
| 浏览器 | Chrome / Edge 最近两个大版本；Safari 16+ | — |

## 6. 失败模式与降级（这一段是 PRD 里最容易被漏掉、最该写的）

| 失败 | 现象 | 系统行为 | 用户看到 |
|---|---|---|---|
| content.json 损坏 | 生成器读不到 | 预检拦截，不发布；生成器回落内置默认值保证能出站 | 「内容文件解析失败，未做任何修改」 |
| 某页生成抛错 | 该页构建失败 | 全部回滚，站点回到发布前 | 「第 N 页失败：<原因>，已回滚」 |
| 两人同时保存 | rev 冲突 | 409 + 字段级 diff | 「XX 在你之前改了首页标题」+ 强制覆盖 |
| 两人同时发布 | 互斥 | 第二个 409 | 「正在发布中，请稍候」+ 进度 |
| 发布中关浏览器 | 后台线程继续 | 完成后状态可查（`/api/publish/status`） | 重开页面看到结果 |
| 公众号同步与保存撞车 | 文件锁 | 串行执行，后者拿到新 rev | 无感 |
| 上传被引用的图并删除 | 引用保护 | 409 | 「该图被 3 个页面引用，先替换再删除」 |
| 会话过期 | 401 | 跳登录，保留未保存草稿（localStorage） | 「登录已过期，你的修改已暂存」 |

## 7. 边界与不做

见 [00-项目一页纸 §3](00-项目一页纸.md)。三条最容易被挑战的，单独说明：

1. **不做 WYSIWYG**：一期纯 textarea 是刻意牺牲体验换结构安全。二期上 Markdown（可 diff、可 Git 版本、无 XSS 面），不是上富文本编辑器。
2. **不做全站 CDN 化 / 前后端分离**：当前 41 页 962 KB，平均 23 KB，首屏 0.8 s 内。分离带来的收益小于复杂度成本。
3. **不做移动端全量编辑**：218 字段需要大屏。移动端只做「看发布状态 + 紧急停用某个产品」，这是明确的取舍，不是遗漏。

## 8. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A-01 | 编辑改电话并发布 | 41 页页脚全部更新；耗时 < 1 s |
| A-02 | 只改一个产品页的简介 | 只有该产品页 mtime 变化，其余 40 页字节不变 |
| A-03 | 双浏览器同时保存 | 第二个收到 409 且能看到差异，不丢内容 |
| A-04 | 人为让生成器抛错 | 41 页哈希全部回到发布前；提示如实 |
| A-05 | 连续点两次发布 | 第二次 409，第一次正常完成 |
| A-06 | 预览后再刷新线上 | 线上仍是旧内容（预览没有污染线上） |
| A-07 | 编辑账号尝试回滚 | 403 |
| A-08 | 删除被 3 页引用的图 | 409 且提示引用页面 |
| A-09 | 恢复到 1 小时前的版本 | 内容回退，且恢复动作本身可再撤回 |
| A-10 | 全站替换「2024」→「2025」 | 命中数正确，替换前自动备份 |

完整 215 条用例见 [10-测试与验收用例](10-测试与验收用例.md)。
