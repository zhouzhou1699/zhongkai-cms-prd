# 风险与合规

> 分三类：**已经出过事的**（安全）、**迟早会出事的**（内容合规与可用性）、**不会出事但要有预案的**（运维）。

## 一、安全（已修复，附证据）

| ID | 问题 | 等级 | 后果 | 修复 | 验证 |
|---|---|---|---|---|---|
| S1 | 未登录任意文件读取：`GET /assets/../admin/server.py` → 200 | 严重 | 可拿 `sessions.json` 免密登录、拿 `users.json` 离线爆破、拿源码找下一个洞、扒 `.git` 历史 | `_static()` 改 realpath + commonpath 双校验 + 拒绝含 `..` 的原始路径 | `curl --path-as-is /assets/../admin/server.py` → 403 |
| S2 | 单共享密码、无账号、无审计 | 高 | 多人共用，无法追责；离职只能改共享密码 | `users.json` + PBKDF2（15 万轮）+ 2 角色 + `audit.log` | 编辑越权 403；日志 20+ 类动作 |
| S3 | 缺 `secret.json` 回落默认密码 `admin123` | 高 | 换机器/重装即回默认密码 | 缺失时强制首登改密，不让人直接进 | 新实例首登跳改密 |
| S4 | 会话在内存、无过期、改密不踢人 | 中 | token 泄露后永久有效 | 落盘 `sessions.json` + 12 h 过期 + 改密/登出踢全端 | 改密后旧会话 401 |
| S5 | 默认监听 0.0.0.0 + 明文 HTTP + Cookie 无 Secure | 中 | 局域网可嗅探 | 生产走 Nginx 反代 443；Cookie 加 Secure/SameSite | 线上检查 Set-Cookie |
| S6 | 上传无频率/总量限制 | 中 | 写满磁盘 | 上传即压缩（≤1920/WebP）+ 12 h 未引用可清理 | 8 MB 原图 → 压缩后入库 |
| S7 | 编辑账号可越权触发发布 | 中 | 非预期上线 | 明确放开（设计决策：编辑需要发布权），并在权限矩阵写清 | 见 02 文档角色表 |

**剩余加固建议（不影响可用性）**：CSP 细化（禁 inline script）、上传文件二次校验 magic bytes、`/api/*` 加简单速率限制、审计日志按日轮转。

## 二、内容合规

| 风险 | 说明 | 措施 |
|---|---|---|
| 客户名单使用 | 基地页提到京东、字节跳动、人瑞等企业项目 | 只用「入驻企业/服务客户」的事实陈述，不使用客户 logo 与商标；对外可脱敏为「头部互联网企业」 |
| 宣传口径 | 「1,929 个固定作业席位」「58 所合作院校」「29 家头部科技企业」等数字 | 每个数字可追溯到基地台账；对外发布前由业务确认；文案不用「最」「第一」等绝对化用语 |
| 采访/报道转载 | 资讯分类含「国家政策」，会转载政策原文 | 只做摘要 + 原文链接，不全文转载；标注来源 |
| 公众号同步版权 | 自动抓取本企业公众号文章 | 只抓自有公众号（绑定的是企业号），不抓第三方 |
| ICP 备案 | 站点底部备案号 `鲁ICP备2021006930号` | 由 `site.icp` 字段统一维护，改一次全站生效 |
| 个人信息 | 未来留言表单会收集姓名/手机 | 表单加隐私说明与同意勾选；线索数据仅存本地 JSONL，不外发第三方 |

## 三、可用性风险

| 风险 | 触发条件 | 影响 | 预案 |
|---|---|---|---|
| 单人维护 | 系统由一个产品经理维护 | 人员变动即失传 | 本仓库文档 + `运营后台使用手册.md`（485 行）+ 代码注释写「为什么」 |
| 无自动化 CI | 测试脚本手工跑 | 回归靠人 | 路线图 P2：把 6 个脚本挂到发布前钩子 |
| 无监控/告警 | 站点挂了没人知道 | 长时间不可用 | 路线图 P2：外部探活（每分钟请求首页，异常推企业微信） |
| 单机部署 | 一台服务器 + 静态文件 | 宕机即全站不可用 | 静态产物可秒级迁到任意 Nginx / CDN；content.json 在 git 里，可全量重建 |
| 生成器 f-string 拼 HTML | 无转义兜底 | 运营填 `<` 会破版式 | 已修 title/description 的 escape；正文类字段待改 Markdown |
| 依赖 Playwright（公众号同步） | 版本升级会破 | 同步任务失败 | 失败不阻塞发布（同步是旁路任务）；面板提供手动「立即同步一次」 |

## 四、数据风险

| 风险 | 说明 | 措施 |
|---|---|---|
| 内容丢失 | 曾存在（整份覆盖无锁） | rev 乐观锁 + 跨进程文件锁 + 60 份快照 + git |
| 误删不可逆 | 删除产品/基地会删 HTML + 清引用 | 二次确认 + 输入名称 + 备份中保留删除前页面 |
| 图片孤儿 | 删除后残留 | 引用计数 + 清理未引用（仅 12 h 前） |
| 备份不含内容 | 曾存在（只备 HTML） | 备份强制含 `content.json` + `meta.json` |
| 恢复后再次被覆盖 | 只恢复 HTML 时会发生 | 恢复可选择「只回页面」或「页面 + 内容」 |

## 六、合规检查清单（每次对外发布前）

- [ ] 数字类表述有出处（席位 / 院校 / 客户数）
- [ ] 无绝对化用语（最、第一、唯一、顶级）
- [ ] 客户名称使用已获授权，或已脱敏
- [ ] 政策转载标注来源与日期
- [ ] 图片有商用授权（自有拍摄 / 授权素材 / AI 生成已标注）
- [ ] 备案号正确且可点（工信部链接）
- [ ] 联系信息与 `site.*` 一致
- [ ] 无「承诺性」文案（如「保证通过」「100% 准确率」）
