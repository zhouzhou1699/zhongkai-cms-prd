# 测试与验收用例

> 编排方式：接口层（自动化）+ 界面层（Playwright 脚本截图断言）+ 破坏性验证（人为故障注入）+ 人工走查（发布前）。
> 本文给的是**用例组织方法与关键断言**，不是 215 条的全量抄录。

## 一、测试分层

| 层 | 形式 | 数量 | 跑法 | 覆盖 |
|---|---|---|---|---|
| L1 接口冒烟 | Python 脚本，直打 HTTP | 57 check | `python _smoke_admin.py` | 认证、乐观锁、发布、预览、历史、备份、图库、账号、审计 |
| L2 界面回归 | Playwright 截图 + DOM 断言 | 24 check | `python _ui_admin_v2.py` | 登录、编辑、搜索定位、预览、6 个工具页、diff、发布进度、菜单、改密 |
| L3 布局检查 | Playwright 双视口 | 9 check | `python _ui_layout_check.py` | 1440 / 390 无横向溢出、无 404 资源、预览样式生效 |
| L4 破坏性验证 | 人为移走生成器 / 杀进程 | 16 check | `python _test_rollback.py` | 发布失败 → 41 页哈希不变 → 手动回滚可还原 |
| L5 冲突与角色 | Playwright 双会话 | 12 check | `_ui_conflict_draft.py` / `_ui_editor_role.py` | 冲突弹窗、强制覆盖、草稿恢复、编辑角色越权 403 |
| L6 人工走查 | 清单 | 20 项 | 发布前 | 文案、图片、导航、移动端 |

合计自动化断言 118 项 + 人工 20 项 + 用例库 215 条（含参数化）。

## 二、关键用例（带断言，可直接照抄）

### A. 认证与权限

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|

| ID | 用例 | 步骤 | 期望 |

## 四、用例库组织方式（215 条）

`测试用例-通用数据标注平台-20261024.md` 的编排经验直接搬了过来：

```
按「模块 × 操作类型」二维矩阵组织：
  模块：登录 / 内容编辑 / 发布 / 回滚 / 历史 / 搜索 / 图片 / 账号 / SEO
  操作类型：正常流 / 边界值 / 异常流 / 权限 / 并发
每条用例字段：ID / 前置 / 步骤 / 期望 / 优先级 / 自动化（是/否/脚本名）
```

**为什么用二维矩阵**：一维列表最容易漏「异常流 × 某模块」。矩阵法逼你把每个格子填满，漏的那格一眼可见。
