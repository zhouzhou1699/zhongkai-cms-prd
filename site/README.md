# 真实官网 · 静态镜像

这里是**线上真实产物**的原样拷贝：40 个 HTML + `assets/`（CSS 235 KB、JS 28 KB、图片与视频 18 MB）。

- 由 `_build/pagebuild.py` 的生成器从 `content.json` 渲染出来的静态文件
- 不是设计稿、不是重构版，就是这个系统跑到今天的样子
- 前台在 GitHub Pages 上是静态托管，所以：**登录页能看，但登录接口不存在**；表单类按钮没有后端

## 两种用法

| 目的 | 怎么用 |
|---|---|
| 看设计 | 直接点开 `index.html`（或 Pages 上的 `/site/`） |
| 看结构 | 配合 [../docs/04-信息架构.md](../docs/04-信息架构.md) 的 41 页树对照 |

## 为什么保留这些「已知缺陷」

这份拷贝是**证据**，不是发布品。所以刻意没有修：

| 现象 | 说明 | 对应文档 |
|---|---|---|
| 首页统计条数字在动画中会数到一半（3 / 1,086 / 33 / 16） | 数字滚动动画依赖 `requestAnimationFrame`，headless 截图会截到中间帧；真实浏览器里会滚到 5 / 2,000+ / 60+ / 30+ | — |
| `robots.txt` 的 Sitemap 指向 `http://127.0.0.1:6993/sitemap.xml` | **真实缺陷**：`domains.json` 的 `main` 还是内网地址，发布时被原样写进 robots.txt | [docs/11-风险与合规.md](../docs/11-风险与合规.md) R-05 |
| `sitemap.xml` 里全是 `127.0.0.1:6993` | 同上 | 同上 |
| 「预约咨询 / 提交需求」点了没反应 | **真实缺陷**：全站只有登录页有 `<form>`，没有任何提交接口 | [docs/02-用户与需求.md](../docs/02-用户与需求.md) F-17 |
| 出站链接原为 `http://127.0.0.1:6993` / `:4123` | 同上，`domains.json` 未切正式域名。**镜像里已用 `scripts/mirror_links.py` 改写成相对路径**，否则在 Pages 上点不动；原始形态保留在 git 首个 site 提交里 | — |
| `运营后台使用手册.html` 未包含 | 含服务器路径、端口、重置密码命令等内部信息，不适合公开 | — |
| `login.html` 保留 | 登录页本身是产品的一部分（改版后的视觉与交互）；接口不在静态托管里 | — |

## 镜像做了哪一处改动

线上产物里有 64 行内网绝对链接（`http://127.0.0.1:6993/xxx.html` 与产品独立站 `:4123/:4124/:4125`），
本机与线上能跑，但静态托管点不动。所以 `scripts/mirror_links.py` 把它们改写成相对路径：

| 原 | 改为 |
|---|---|
| `http://127.0.0.1:6993/products.html` | `products.html` |
| `http://127.0.0.1:4123/`（标注平台独立站） | `product-annotation.html` |
| `http://127.0.0.1:4124/`（3D 点云独立站） | `product-3d.html` |
| `http://127.0.0.1:4125/`（模型训练独立站） | `product-model-train.html` |

**除这 64 行外，其余字节与线上一致**（`--check` 模式可复跑验证）。这是为了「可点」，不是为了「更好看」。

## 与后台的关系

```
site/          ← 你看到的官网（访客视角，40 页静态 HTML）
prototype/     ← 运营后台的可点原型（编辑者视角）
docs/          ← 后台的真实规格（PRD / IA / 字段字典 / 接口）
```

后台真实代码（`admin/server.py` 3,039 行）不在本仓库——这个仓库是**产品交付物**，不是实现仓库。
